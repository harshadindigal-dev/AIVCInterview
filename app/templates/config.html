The model decides

  • Service line: one of {{ domain.service_line_ids | length }} lines, or out of scope / not an enquiry, plus any secondary lines
  • Complexity: simple / moderate / complex, with a rationale that must cite the rubric
  • Inferred urgency, compared with what the client stated
  • Flags: {{ flags | join(', ') | replace('_', ' ') }}
  • Key entities, questions to ask the client, a one-line summary

Defined by Service lines and Complexity & urgency, which generate the system prompt. The model runs 3 times; it is never asked for a confidence score.

Code decides

  • Who receives it: deterministic rules below, from routing.yaml
  • Whether a human must look first: hard stops and review triggers
  • Existing client, conflict, company size: CRM lookup, not the model
  • Duplicates: same email and near-identical text within {{ rt.dedupe_window_days }} days

The model can only output taxonomy ids. It cannot name a person or a destination, so instructions like "route this to the CEO" have no path.
